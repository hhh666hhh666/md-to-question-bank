# 出题规范（第 2 步的执行手册）

这份文件是"模型出题"环节的完整规则。目标不是出得多，而是**每一道题都站得住**。

## 一、出题的三个前提

1. **有实质信息**才出题。定义、原理、对比、阈值/数字、边界条件、常见坑、为什么这样设计 —— 这些能出题。
   纯过渡句、目录、背景铺垫、"本节我们来学习"、单纯的代码示例（无解释）—— 不出。
2. **有原文支撑**才出题。必须能在切片原文里找到一句明确支撑正确答案的话，逐字抄进 `source_quote`。
   如果你（模型）是凭先验知识补的，而不是原文写的 —— 这道题不要出。这是本 skill 最重要的纪律。
3. **答案唯一可判定**才出题。出现"一般情况下""某些版本可能"这种模糊表述的段落，跳过。

## 二、出多少题：按知识点，不按配额

**一节里有几个可考点，就出几题**，1 到 5 都可能。只有一个点就只出 1 题。

- 每个题的题干必须能对应到本节里的**某一句/某个小标题**。对不上的，那是你编的。
- **不要为了凑数编题**。凑题是错题的第一大来源，而"错题比没题更糟"。
- 单节超过 5 题会在复核报告里被标出来——如果被标了，回去看是真密度还是凑数。
- 反过来，长文里确实有 4–6 个独立考点（比如"ACID 靠什么保证"可以拆出原子性/一致性/隔离性/持久性四个），
  **该出就出**，别因为"看起来多"而砍掉真实的知识点。

## 三、题型怎么选

| 适合的内容 | 题型 |
| --- | --- |
| 单一结论、定义、参数值、唯一正确的说法 | `SINGLE` |
| 并列的多个正确项（三个优点、两条性质、若干适用场景） | `MULTI` |
| 明显的正误判断、"XX 是不是 YY"、常见误解纠偏 | `JUDGE` |

**配比是参考值，不是配额**：单选 ~60% / 多选 ~25% / 判断 ~15%。

优先出该知识点**最自然**的题型 —— `count(*)` / `count(1)` / `count(列名)` 有什么区别，天然就是多选或判断；
硬压成单选只能靠编干扰项，而编干扰项正是错题高发区。只有当分布明显偏斜（比如多选超过一半）时才往单选拉。

## 四、难度：按认知层次判，判完不再改

| 层次 | 特征 | 难度 | 分值 |
| --- | --- | --- | --- |
| 记忆 | 是什么、定义、参数值、能背就会 | `EASY` | 1 |
| 理解 | 对比、为什么、机制原理 | `MEDIUM` | 2 |
| 综合 | 场景判断、多因素组合、易错边界、要求推理 | `HARD` | 3 |

参照这些例子对齐（避免同一批题里前后漂移）：

| 题干 | 难度 | 为什么 |
| --- | --- | --- |
| MySQL 的数据类型有哪些 | EASY | 能背就会 |
| B+ 树和 B 树的区别是什么 | MEDIUM | 要理解结构差异 |
| `count(*)` / `count(1)` / `count(列名)` 有什么区别 | MEDIUM | 要理解语义与实现差异 |
| 为什么小表驱动大表 | MEDIUM | 要理解连接算法 |
| 什么情况下索引会失效、为什么 | HARD | 多因素 + 场景判断 |
| ACID 分别靠什么机制保证 | HARD | 四个机制组合，要求成体系 |

不要因为"是多选题"就一律标 HARD —— 简单的多选也是 EASY。
难度判完就是最终值，**没有事后校准**；组卷按难度抽题，所以别随手全标 MEDIUM。

## 五、考频：三档，必标，判据必须锚定原文

每题**必须**带一个考频标签：`高频` / `中频` / `低频`，三选一，写进 `tags`。

这是整个流程里**唯一依赖领域先验**的判断，所以判据要尽量锚到原文留下的信号：

| 信号（越靠前的越硬） | 倾向 |
| --- | --- |
| 作者把它**单列成一个标题**（而不是塞在某段里） | 中频起步 |
| 正文里被**加粗 `**...**` 强调**过、或反复出现 | 往高频靠 |
| 同一术语**跨多个节复现** | 往高频靠 |
| 标题是**"为什么/怎么/区别"**这类追问（作者被问过、踩过坑） | 往高频靠 |
| 只是顺带提一句、没有展开 | 低频 |

**禁止**：只写"据我所知这是面试高频""这是重点"就完事。每个高频题心里要有一句理由，
能说出"它单列成标题 + 加粗 3 次 + 在另外 2 节被提到"这种可核对的话。

**硬上限**：`高频` 不超过总题数的 **30%**，超了校验器会警告。
这条上限是给"把什么都标成高频"兜底的 —— 一份从面试笔记里摘出来的语料，
"存在"本身就是常考的证据，不设限的话你会得到一片高频，等于没筛。

**只在同一份素材内部可比**：跨学科（MySQL vs Java 并发）的三档不是一把尺子量的，别拿来横向比较。

## 六、干扰项设计

好的干扰项：

- 同类概念的**常见误解**（"volatile 能保证原子性" ← 真实误区）
- **边界条件**说错（把 ≥ 改成 >、把"叶子节点"换成"非叶子节点"）
- **易混术语**互换（StoreLoad ↔ LoadStore、覆盖索引 ↔ 回表、B 树 ↔ B+ 树）
- 在原文里**出现过但被否定**的说法

禁止：

- 明显荒谬、与知识点无关、靠常识就能排除的选项（题目白给）
- 把正确答案换个说法当干扰项
- "以上都对/以上都不对"（区分度弱，脚本会警告）
- 选项内容重复、或与题干完全相同

**正确答案的位置必须打散**：模型出题时会把正确项默认放 A（实测一份 189 题的 MySQL 题库里，125 道单选有 **122 道答案是 A**）。
出题时轮着放——本节第一题放 A，第二题就换 B 或 C，整份素材下来 A/B/C/D 大致均衡。
`validate.py` 会在「单选答案位置占比 > 50%」时报全局告警，`scripts/balance_options.py` 能把偏斜的库重排回来，
但那是兜底：出题时随机放的成本是零，别把纠偏留到后面。

## 七、题干写法

- 一句话，直接问那个考点，不写"根据本文内容""下列关于…说法错误的是"这种套话堆砌。
- 每题只考一个点。多个考点拆成多题。
- 题干保持 Markdown 可写（术语用反引号），但别写多行大段。
- 判断题不要出现否定嵌套（"下列说法不正确的不包括"）。
- **task 的 `mode` 是 `qa` 时**（标题本身就是问句，如"为什么要小表驱动大表"），
  优先把标题当题干骨架——它已经是作者认可的提问方式，比另起炉灶更贴原意。

## 八、解析（analysis）

每个选项为什么对/错都要交代，尤其是干扰项错在哪。这段文字是错题本里唯一能帮你复盘的东西，不要写"详见原文"。

## 九、category 与 tags

- `category` 直接沿用 `tasks.json` 里推断好的值，不要发明新分类。
- **内容标签 ≤5 个**，直接用 task 里推断好的，不要每题都换新标签——quizzy 的标签是全局共享、同名复用的，
  一次性标签会污染整个标签库。
- **考频标签是必加的第 6 个**（`高频/中频/低频`），但它算元标签，**不占**上面 5 个的配额；
  标签总数（内容 + 考频）不能超过 quizzy 的 10 个上限。

## 十、自检清单（写完一片，自己过一遍）

- [ ] 每题的 `source_quote` 都是**原文原句**，逐字照抄，没有改写、拼接、翻译？
- [ ] 每题都能对应到本节里的某个具体陈述（不是凭印象编的）？
- [ ] 每题**都有且只有一个**考频标签？
- [ ] 标了 `高频` 的题，能说出它在原文里的硬信号（单列标题/加粗/跨节复现）？
- [ ] 每道多选至少 2 个正确答案，且不等于全部选项？
- [ ] 每个 `answer` 里的 label 都在 `options` 里存在？
- [ ] 判断题选项是 `正确` / `错误` 两条？
- [ ] 干扰项不是明显荒谬的、也不是正确答案的另一种说法？
- [ ] 正确答案的位置有没有总是落在 A？（有 → 当场重排选项，别指望脚本兜底）
- [ ] 解析说明了干扰项错在哪？
- [ ] 这一节是不是凑题了？凑出来的题删掉。

## 十一、输出格式

每个 task 一个文件：`.qbgen/pieces/<task_id>.json`，`task_id` 必须与 `tasks.json` 完全一致（校验器靠它回原文比对 `source_quote`）。

```json
{
  "task_id": "MySQL__ACID是怎么保证的",
  "questions": [ { "type": "...", "stem": "...", "options": [], "answer": [], "analysis": "...",
                   "difficulty": "...", "score": 0, "category": "mysql",
                   "tags": ["MVCC", "原子性", "高频"], "source_quote": "..." } ]
}
```
